# Career Form Autofill MVP

A Chrome extension that maps application form fields to saved profile data, shows confidence-scored suggestions, and fills only the fields selected by the user. Rule-based matching is the default, with optional local or cloud model assistance for uncertain fields.
就活・インターン・留学などの申込フォームを解析し、保存済みプロフィールから入力候補をプレビューして、利用者が選んだ項目だけを反映するChrome拡張機能です。

## 安全方針

- 入力は拡張機能のボタンを押した場合だけ実行します。
- 送信ボタンは操作しません。自動送信機能はありません。
- パスワード欄、ファイル欄、チェックボックスは対象外です。
- プロフィールは `chrome.storage.local` に保存します。Jevを明示的に有効にした場合だけ、未判定欄のメタデータを外部APIへ送ります。
- `chrome.storage.local` は「端末内保存」ですが、暗号化を保証するものではありません。共用PCでは使用しないでください。

## 対応項目

- 氏名：漢字、全角カナ、半角カナ、姓・名分割、1欄形式
- 連絡先：メール、第2メール、メール確認、電話、郵便番号、住所
- 本人情報：生年月日、性別
- 保護者：氏名、続柄
- 学歴：大学、学部、学科・専攻、入学年月、卒業予定年月
- フォーム形式：テキスト、電話、メール、日付、プルダウン、ラジオ、電話・郵便番号などの分割欄

## Chromeへの導入

1. このrepositoryを取得します（GitHubのCode → Download ZIPでも可）。ZIPなら展開します。
2. Chromeで `chrome://extensions` を開きます。
3. 右上の「デベロッパーモード」をオンにします。
4. 「パッケージ化されていない拡張機能を読み込む」を押します。
5. `manifest.json` が入っている `career-form-autofill` フォルダを選びます。
6. 拡張機能一覧の「詳細」→「拡張機能のオプション」でプロフィールを保存します。

実際の応募先を使わずに確認する場合は [`examples/demo-form.html`](examples/demo-form.html) をChromeで開きます。これは架空のフォームで、送信先や送信ボタンはありません。拡張機能が `file://` ページを読み取れるよう、拡張機能の詳細画面で「ファイルのURLへのアクセスを許可」を有効にしてください。

## Macの連絡先から初期登録

1. Macの「連絡先」で「カード」→「自分のカードを表示」を選び、氏名や連絡先を確認します。自分のカードが未設定の場合は対象のカードを選択し「カード」→「このカードを自分のカードにする」を選びます。[Appleの説明](https://support.apple.com/guide/contacts/adrb3525ca49/mac)
2. 上のApple Intelligenceの手順に従ってMac側ブリッジをインストールします。以前インストールした場合も、更新版のインストールコマンド（Braveなら `./native/install.sh 拡張機能ID brave`）を再実行し、Chromeで拡張機能を再読み込みしてください。
3. 拡張機能のプロフィール設定で「自分の連絡先から取り込む」を押し、macOSの許可を求められたら確認します。連絡先アプリが開く場合があります。
4. 読み込まれた空欄を確認・修正し、「プロフィールを保存」を押します。入力済みの項目は上書きされず、保存前に画面を閉じれば取り込みは確定しません。

氏名、フリガナ、最初のメール・電話番号、最初の住所、生年月日を、カードに存在する範囲で読み取ります。複数ある場合は希望する値か確認してください。大学など連絡先にない項目は手入力してください。連絡先データはMac内で処理し、Apple Intelligenceや外部サービスに送信しません。自分のカードの共有設定によっては一部項目が返らない場合があります。アクセスが拒否された場合はmacOSの「プライバシーとセキュリティ」の連絡先・オートメーションの許可を確認してください。

## 英語プロフィールの作成

日本語プロフィールを入力または連絡先から取り込んだ後、「English profile」の「Apple Intelligenceで英語にする」を押すと、氏名、住所、大学・学部・学科の英語候補を空欄に入力します。既存の英語欄は上書きしません。氏名はフリガナがあればそれを優先します。候補を確認・修正し、プロフィールを保存してください。氏名のパスポート表記や学校の公式英語名は必ず自身で確認してください。全角カナを入力すると半角カナ欄も自動入力します。

英訳にはApple IntelligenceのMac側ブリッジと `fm` の利用準備が必要です。ボタンを押したときだけ翻訳対象の値が端末内のモデルに渡され、外部APIには送られません。モデルの実行時、値がローカルのプロセス引数に含まれます。モデルが利用できないときや不正な応答を返したときは英語欄を変更しません。ブリッジを以前インストールした場合は最新版のインストールコマンドを再実行してください。

## 使い方

1. 応募・申込フォームを開きます。
2. Chromeのツールバーから本拡張機能を開きます。
3. 「現在のフォームを解析」を押します。
4. 入力先・入力値・判定確度をプレビューし、不要な項目のチェックを外します。
5. 「選択した項目を入力」を押します。
6. ページ全体を確認してから、自分で送信します。

判定確度が「要確認」の項目は初期状態で選択されません。ページ側が項目名を変更した場合や、独自UIを使っている場合は検出できないことがあります。

## 判定の仕組み

各入力欄について、次の情報を組み合わせて項目を推定します。

1. HTML標準の `autocomplete`
2. 関連付けられた `label`
3. `name`、`id`、`placeholder`、ARIA属性
4. 入力欄周辺の日本語・英語テキスト
5. 同じグループ内での入力欄の順番と桁数

加えて、`aria-labelledby` / `aria-describedby` の参照先、テーブルの見出し（`th`）、定義リストの見出し（`dt`）、`section-... email` のような複合 `autocomplete` 値も解析します。表記ゆれは「苗字」「名字」「ヨミガナ」「郵便」「居住地」「住所第二」などを含めて扱います。

判定結果には0〜100のスコアを付け、プレビュー上で「高」「中」「要確認」と表示します。

## Apple Intelligenceによる補助判定（macOS 27）

Apple公式の [`fm` CLI](https://developer.apple.com/videos/play/wwdc2026/334/) を使用します。macOS 27に標準搭載され、`fm respond` は既定でオンデバイスモデルを使用します。Jev、Ollama、APIキーやモデルのダウンロードは不要です。Apple Intelligence対応のMacでApple Intelligenceを有効にし、モデルを利用可能にしてください。

1. 上記のChrome導入手順で拡張機能を読み込み、`chrome://extensions` の本拡張機能のID（32文字）をコピーします。
2. ターミナルで展開したフォルダへ移動し、`./native/install.sh 拡張機能ID` を実行します。Braveの場合は `./native/install.sh 拡張機能ID brave`、Edgeの場合は `./native/install.sh 拡張機能ID edge` を実行します。Apple Command Line ToolsのPython 3が必要です。求められた場合は `xcode-select --install` で導入してください。
3. `fm respond "こんにちは"` を試します。利用規約への同意が必要と表示された場合は、表示を確認してから管理者が `sudo fm license` で手続きしてください。Apple Intelligenceやモデルが利用できない場合はmacOSの設定を確認してください。
4. Chromeの拡張機能を再読み込みし、「プロフィール設定」で「Apple Intelligenceを使う」にチェックして保存します。解析時はポップアップを開いたまま待ってください。

通常ルールの判定済み項目と未判定項目から、設問ごとに最大100件までApple Intelligenceで照合します。ラジオ項目や選択肢が不足する項目は対象外です。設問文・入力例や文字数制限（合わせて最大80文字）と、分類・入力形式の候補をローカルのブリッジに渡します。AIは、ハイフンなしの番号、空白なしの氏名、スラッシュ区切りの生年月日など、用意された形式から選びます。選ばれた形式はブラウザ側で保存済みの値に適用し、「要確認」として表示します。保存されたプロフィール値・フォームの入力値・URLは渡しません。ただし設問文自体に個人情報が含まれる場合はモデルに渡ります。AIの結果がルール判定と異なる場合や判断できない場合は、元の候補を「要確認」とし初期状態では選択しません。AIが新たに提案した項目も初期状態では選択しません。接続や時間切れなどで照合できなかった項目はルール判定を表示し、一部のみ照合できた場合はその旨を表示します。AI候補を含む結果は必ずプレビューされ、選択した項目だけを手動で入力します。フォームの送信は行いません。初回や混雑時は最大57秒程度待ち、時間内に処理できない項目は未照合となります。

ブリッジはChrome Native Messagingを使い、指定された拡張機能IDだけを許可します。macOSのBraveはChromeのホスト登録先を使用します。拡張機能IDが変わった場合はインストールを再実行してください。削除するには `~/Library/Application Support/Google/Chrome/NativeMessagingHosts/com.career_form_autofill.apple_fm.json` と `~/Library/Application Support/Career Form Autofill` を削除します。Apple Intelligenceが有効な場合、既存のJev・ローカルLLM設定より優先されます。

## ローカルLLMによる補助判定（任意）

通常ルールで判定できなかった設問を優先し、任意でローカルLLMに最大2問だけ再判定させられます。各設問は候補を最大4種類に絞った短い質問として並列処理します。これは「すべての言い回し」を固定の辞書に書き切るより、文脈を含む設問（例: 「日中につながる番号」「学校・教育機関の名称」）に強くするための補助です。LLMは2.6秒で打ち切られ、間に合わない場合も通常ルールの結果を3秒以内に表示します。

1. PCに [Ollama](https://ollama.com/) を入れ、例えば `ollama run qwen2.5:3b` でモデルを一度起動・取得します。
2. 拡張機能の「プロフィール設定」で「Ollamaなど、PC上で動くLLMを使う」を有効にします。
3. API URL は標準の `http://127.0.0.1:11434/api/chat`、モデル名は取得したモデル名に合わせます。保存時にモデルを準備し、その後30分間メモリに保持します。
4. Braveなどのブラウザ拡張から接続する場合は、Ollamaを終了してからユーザー環境変数 `OLLAMA_ORIGINS` に `chrome-extension://拡張機能ID` を設定し、Ollamaを起動し直します。
5. フォームを解析します。LLMが動いていない、403、時間切れなどの場合は、LLMを待たず通常ルールの結果だけを表示します。

LLMに送るのは、80文字以内に短縮した候補欄のラベル・周辺の設問文と、最大4種類の分類候補だけです。保存した氏名・住所・メールアドレスなどのプロフィール値と、入力する値は送信しません。接続先は `localhost` / `127.0.0.1` / `::1` のHTTP URLだけに制限しています。LLMの結果もプレビューで確認してから入力され、送信操作は行いません。

## Jevによる補助判定（任意・実験的）

TypeSafe Jev は文章生成ではなく、候補からの選択・確率・confidenceを返すクラウドAPIです。設定で「Jevを使う」を有効にし API key を保存すると、通常ルールが**未判定**にした欄だけを最大20件まとめて問い合わせます。ルールで既に判定した欄は再判定しません。

- 送るもの: フォーム言語、ラベル、`name`/`id`等のHTML属性、入力種別、140文字以下の周辺文、あらかじめ絞った項目候補
- 送らないもの: 保存プロフィールの値、実際に入力する値、フォームのURL
- 採用条件: 選択肢の確率が85%以上、かつconfidenceが0.75以上。`none`・低確信度の回答は未入力のままです。
- API key: 実験用として `chrome.storage.local` に平文保存します。共有PCや配布版には使わないでください。

ポップアップでは解析前に `日本語` または `English` を選択します。Englishを選ぶと、English profileに保存したローマ字氏名・英語住所・学校情報を使用します。メール・電話・生年月日・郵便番号は共通です。

## 開発者向けテスト

Node.js 20以降があれば、追加パッケージなしで構文検査と主要テストを実行できます。

```bash
npm run check
npm run test:local
```

依存不要テストでは、最大2問、並列短問、時間切れ、403、Jevの閾値処理、英語プロフィール、住所・学部学科の矛盾防止などを検査します。DOM統合テストまで実行する場合は `npm ci` 後に `npm test` を使います。2026-09-23にNode.js 22で `npm run check` と `npm test`（21件）を実行し、いずれも通過しました。Chrome上の手動操作はこの検証に含みません。

## 構成と判断

`content-script.js` がフォームを走査し、`autofill-core.js` がルールとスコアで候補を作ります。`popup.js` は候補を表示して利用者の選択を待ち、選択した項目だけをcontent scriptへ渡します。任意のLLM/Jev呼び出しは `background.js` に分離しています。ブラウザ内でまず規則による判定を行うため、外部サービスがなくても基本機能を使えます。

`chrome.storage.local` にはプロフィール、ローカルLLM設定、Jevの有効化設定とAPI keyを保存します。クラウドJevは有効化した場合だけ未判定欄のラベル・HTML属性・周辺文を送ります。フォーム上の文に個人情報が含まれる場合は、その文が送信対象になる可能性があります。実際のフォームで有効にする前に確認してください。

## MVPの制約

「すべてのフォーム」を完全に保証することはできません。言い回しは無限にあり、ラベルのない欄や同じ設問内に本人・保護者の情報が混在する欄は、人間にも曖昧になり得ます。確度が低い候補は選択解除のまま確認してください。特に次は初期版の対象外です。

- 別ドメインのiframe内にある入力欄
- Shadow DOM内の入力欄
- Canvasなど、通常のHTML入力要素を使わない独自UI
- ページ固有の特殊な和暦・住所検索・大学検索ウィジェット
- 入力後に別の入力欄が動的生成された場合（再解析で対応できることがあります）

実際に使って誤判定したフォームについて、URLを保存せずに「ラベル、name/id、正しい項目」のローカルルールを追加できる仕組みが次の改善候補です。

フォームの構造から、姓名・フリガナ・生年月日・電話番号の分割、学部と学科、市区町村と番地の結合を行います。年齢は完全な生年月日から今日の満年齢を算出します。職業はプロフィールに登録した場合にだけ入力します。
